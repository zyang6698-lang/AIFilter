# DeepSightAI 数据库设计文档

## 1. 概述

DeepSightAI 使用 **PostgreSQL** 作为持久化存储，通过 `Npgsql` 驱动程序进行交互。数据库模块封装在 `DeepSightDB` 项目中，核心服务类为 `DatabaseHelper`，实现 `IDatabaseService` 接口。

### 1.1 技术栈
| 组件 | 技术 |
|------|------|
| 数据库引擎 | PostgreSQL |
| 驱动程序 | Npgsql (.NET PostgreSQL 驱动) |
| 序列化 | Newtonsoft.Json |
| 配置管理 | JSON 文件 (`postgresql_config.json`) |
| 缓存 | 内存缓存 (`BoardStatCache`) + XML 持久化 |

### 1.2 连接配置 (`PostgreSqlConfig`)
配置文件路径：`{AppDomain.BaseDirectory}/configs/postgresql_config.json`

| 参数 | 默认值 | 说明 |
|------|--------|------|
| Host | `localhost` | 服务器地址 |
| Port | `5432` | 端口 |
| Database | `deepsight` | 数据库名称 |
| Username | `postgres` | 用户名 |
| Password | `deepsightai` | 密码 |
| Timeout | `30` | 连接超时（秒） |
| MaxPoolSize | `100` | 最大连接池 |
| MinPoolSize | `1` | 最小连接池 |
| WriteBufferSize | `16384` | 写缓冲区（字节） |
| ReadBufferSize | `16384` | 读缓冲区（字节） |
| TcpKeepalive | `true` | TCP 保活 |
| KeepaliveInterval | `60` | 保活间隔（秒） |
| Pooling | `true` | 启用连接池 |
| NoResetOnClose | `true` | 关闭时不重置连接 |

## 2. 数据库表结构

### 2.1 Panels（面板主表）

存储每块面板的基本信息，以 `SerialNumber` 作为唯一业务键。

```sql
CREATE TABLE IF NOT EXISTS Panels (
    Id              SERIAL PRIMARY KEY,
    MachineId       TEXT NOT NULL,          -- 检测机台ID
    SerialNumber    TEXT NOT NULL UNIQUE,    -- 面板序列号（唯一）
    LotNumber       TEXT NOT NULL,          -- 批次号
    ProductSerial   TEXT,                   -- 料号（可选）
    DetectionDate   TIMESTAMP NOT NULL,     -- 检测时间
    AviCreationTime TIMESTAMP              -- AVI 创建时间（用于稼动率计算）
);
```

### 2.2 PanelSides（面板面别表）

存储面板每一面（A面/B面）的检测结果，与 `Panels` 表是一对多关系。

```sql
CREATE TABLE IF NOT EXISTS PanelSides (
    Id          SERIAL PRIMARY KEY,
    PanelId     INTEGER NOT NULL,           -- 关联 Panels.Id
    Side        TEXT NOT NULL,              -- 面别：'A' 或 'B'
    HeatPoints  TEXT,                       -- 缺陷点列表（JSON 字符串）
    AviState    INTEGER DEFAULT 0,          -- AVI 状态：0=未运行, 1=OK, 2=NG
    AiState     INTEGER DEFAULT 0,          -- AI 状态：0=未运行, 1=OK, 2=NG
    VvsState    INTEGER DEFAULT 0,          -- VVS 状态：0=未运行, 1=OK, 2=NG
    VrsState    INTEGER DEFAULT 0,          -- VRS 状态：0=未运行, 1=OK, 2=NG
    FinalState  INTEGER DEFAULT 0,          -- 最终状态：0=待处理, 1=最终OK, 2=最终NG
    TestState   INTEGER DEFAULT 0,          -- 测试状态：0=未测试, 1=一致, 2=不一致, 3=测试中, 4=异常
    LastTestTime TIMESTAMP,                 -- 最近测试时间
    DrawInfo    TEXT,                       -- 绘制/阈值信息（JSON）
    FOREIGN KEY (PanelId) REFERENCES Panels(Id) ON DELETE CASCADE
);
```

### 2.3 EmployeeReports（员工报告表）

存储员工 VRS 复判操作记录。

```sql
CREATE TABLE IF NOT EXISTS EmployeeReports (
    Id           SERIAL PRIMARY KEY,
    EmployeeID   TEXT NOT NULL,             -- 员工ID
    SN           TEXT NOT NULL,             -- 面板序列号
    AllNGNumber  INTEGER NOT NULL,          -- 全部NG报点数
    StartTime    TIMESTAMP NOT NULL,        -- 操作开始时间
    EndTime      TIMESTAMP NOT NULL,        -- 操作结束时间
    VRSOKNumber  INTEGER NOT NULL           -- VRS 判定OK的报点数
);
```

| `idx_panelsides_panelid_side` | PanelSides | (PanelId, Side) | 唯一约束 + UPSERT 冲突检测 |

### 3.2 单列索引
| 索引名 | 表 | 列 | 用途 |
|--------|----|----|------|
| `idx_panels_detectiondate` | Panels | DetectionDate | 时间范围查询 |

| `idx_panels_lotnumber` | Panels | LotNumber | 按批次查询 |
| `idx_panels_productserial` | Panels | ProductSerial (WHERE NOT NULL) | 按料号查询（部分索引） |
| `idx_panelsides_panelid` | PanelSides | PanelId | JOIN 优化 |
| `idx_employeereports_starttime` | EmployeeReports | StartTime | 时间范围查询 |
| `idx_employeereports_endtime` | EmployeeReports | EndTime | 时间范围查询 |

### 3.3 复合索引
| 索引名 | 表 | 列 | 用途 |
|--------|----|----|------|
| `idx_panels_machineid_detectiondate` | Panels | (MachineId, DetectionDate DESC) | 按机台+时间排序查询 |

## 5. 架构设计

### 5.1 单线程队列模型

`DatabaseHelper` 使用 **单线程消费者队列** 模式处理所有数据库操作：

```
调用方线程                      数据库线程 (DatabaseThread)
    │                                │
    │  _dbQueue.Add(action)          │
    ├───────────────────────────────►│
    │                                │ action(connection)  // 顺序执行
    │                                │
    │  TaskCompletionSource.Task     │
    │◄───────────────────────────────┤  tcs.SetResult(...)
```

- **写操作** (`SavePanelSide`, `SaveEmployeeReport`)：入队后立即返回（fire-and-forget）
- **读操作** (`GetPanelsData`, `GetEmployeeReports` 等)：返回 `Task<T>`，通过 `TaskCompletionSource` 等待结果
- **优势**：避免并发连接竞争，保证操作顺序性；单连接复用预编译命令

### 5.2 预编译命令 (Prepared Statements)

以下两个高频操作使用预编译命令以提升性能：

| 命令 | SQL | 用途 |
|------|-----|------|
| `_upsertPanelCmd` | `INSERT INTO Panels ... ON CONFLICT (SerialNumber) DO UPDATE ... RETURNING Id` | Panel UPSERT |
| `_upsertPanelSideCmd` | `INSERT INTO PanelSides ... ON CONFLICT (PanelId, Side) DO UPDATE ...` | PanelSide UPSERT |

### 5.3 内存缓存层 (`BoardStatCache`)

为避免频繁查询数据库获取统计数据，系统维护了一个 **内存统计缓存**：

- **按天自动重置**：跨日自动清空并重建
- **增量更新**：每次 `SavePanelSide` 时同步更新缓存中的 `BoardStat` 统计
- **XML 持久化**：每 100 条记录或进程退出时，按小时保存到本地文件
- **按机台统计**：支持全局和单机台两个维度的统计查询
- 持久化路径：`%LocalAppData%/DeepSightAI/BoardStatCache/{yyyyMMdd}_{HH}.xml`

## 6. 数据写入操作

### 6.1 单条写入 — `SavePanelSide(PanelSideRecord)`

**流程：**
1. 参数验证（SerialNumber、Side、Data 非空）
2. 提前序列化 `HeatPoints` 为 JSON
3. 入队操作：开启事务 → UPSERT Panel → UPSERT PanelSide → 提交事务
4. 异常时回滚事务

**UPSERT 策略：**
- `Panels`：以 `SerialNumber` 冲突时更新 `DetectionDate`，返回 `Id`
- `PanelSides`：以 `(PanelId, Side)` 冲突时更新所有检测状态字段

### 6.2 批量写入 — `SavePanelSidesBatch(records, batchSize=100)`

- 预先过滤无效记录并序列化 JSON
- 分批（默认每批 100 条）提交事务
- 单批失败时回滚该批，不影响其他批次

### 6.3 CSV 导入 — `ImportFromCsvData(panelsCsvLines, panelSidesCsvLines)`

**三阶段流程：**
1. **解析 Panels CSV** → 构建 `panelsDict` 字典
2. **并行解析 PanelSides CSV** → `Parallel.For` 利用多核加速，使用 `ParseCsvLineWithJson` 处理内嵌 JSON
3. **批量写入数据库** → 每批 500 条，使用预编译命令

### 6.4 员工报告写入 — `SaveEmployeeReport(EmployeeReport)`

简单 INSERT 操作，无 UPSERT 逻辑。

### 6.5 状态更新操作

| 方法 | 更新字段 | 说明 |
|------|----------|------|
| `UpdateTestStateAsync(sn, side, testState, testTime)` | TestState, LastTestTime | 更新模型验证测试状态 |
| `UpdatePanelSideAiStateAsync(sn, side, heatPoints, aiState)` | HeatPoints, AiState | 二次推理后更新 AI 结果 |

## 7. 数据读取操作

### 7.1 核心查询模式

所有面板查询使用统一的 `ExecutePanelQuery` 辅助方法：
- `Panels LEFT JOIN PanelSides` 关联查询
- 按 `Panel.Id` 分组聚合，每个 Panel 包含多个 `SideData`
- 自动处理 NULL 值和 JSON 反序列化（HeatPoints → `List<DetectInfo>`）

### 7.2 查询接口一览

| 方法 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `GetPanelsData(start, end, partNumber?)` | 时间范围 + 可选料号 | `List<PanelDataRecord>` | 按时间范围查询，支持料号过滤 |
| `GetPanelsDataByMachineAndLot(machineId, lotNumber)` | 机台ID + 批次号 | `List<PanelDataRecord>` | 按机台和批次查询 |
| `GetAllMachineIds()` | 无 | `List<string>` | 获取所有不重复机台ID |
| `GetRecentLotNumbers(page, pageSize)` | 分页参数 | `List<string>` | 按最新检测时间倒序分页获取批次号 |
| `GetTotalLotCount()` | 无 | `int` | 不重复批次总数 |
| `GetEmployeeReports(start, end)` | 时间范围 | `List<EmployeeReport>` | 员工报告查询 |
| `GetEmployeeIds(start, end)` | 时间范围 | `List<string>` | 时间范围内不重复员工ID |

### 7.3 统计查询 (`BoardStatCache`)

| 方法 | 说明 |
|------|------|
| `BoardStatCache.GetTodayStat()` | 获取当天全局统计（从内存缓存） |
| `BoardStatCache.GetTodayStatForMachine(machineId)` | 获取指定机台当天统计 |
| `PanelDataRecord.GetBoardStat(records)` | 从查询结果计算统计（数据库直查，开销较大） |

**BoardStat 统计字段：**

| 字段 | 说明 |
|------|------|
| AviPanelCount | AVI 检测面板总数 |
| AviPanelOKCount | AVI 两面均 OK 的面板数 |
| AiPanelOKCount | AI 两面均 OK 的面板数 |
| AiFilterCount | AI 报点总数 |
| AiFilterOKCount | AI 过滤 OK 的报点数 |
| AiFilterUninspectedCount | 未检测报点数 |
| Utilization | 平均稼动率 (%) |

## 8. 数据维护操作

### 8.1 清空数据 — `ClearAllData()`

按外键依赖顺序在事务中执行：
1. `DELETE FROM PanelSides`
2. `DELETE FROM EmployeeReports`
3. `DELETE FROM Panels`
4. 重置所有序列（`ALTER SEQUENCE ... RESTART WITH 1`）

### 8.2 数据库初始化 — `InitializeDatabase(config?)`

1. 尝试连接目标数据库
2. 若数据库不存在（错误码 `3D000`），连接 `postgres` 库自动创建
3. 创建所有表结构 (`CREATE TABLE IF NOT EXISTS`)
4. 创建所有索引 (`CREATE INDEX IF NOT EXISTS`)

## 9. 数据模型类

### 9.1 写入模型

**`PanelSideRecord`** — 单面写入记录
```
MachineId, SerialNumber, LotNumber, ProductSerial, DetectionDate, AviCreationTime, Side, Data(SideData)
```

**`SideData`** — 面别检测数据
```
Side, DetectPoints(List<DetectInfo>), AviState, AiState, VvsState, VrsState, FinalState, TestState, LastTestTime, DrawInfo
```

**`DetectInfo`** — 单个缺陷点
```
DefectName, DefectType, DefectShape, RoiX/Y, Width/Height, OriginRoiX/Y, OriginWidth/Height,
ImagePath, DrawInfo, AIStatus, VVSStatus, VrsState, FinalState
```

### 9.2 读取模型

**`PanelDataRecord`** — 完整面板记录（包含关联的 Sides）
```
Id, MachineId, SerialNumber, LotNumber, ProductSerial, DetectionDate, AviCreationTime, Sides(List<SideData>)
```

### 9.3 状态枚举说明

**检测阶段状态 (AviState / AiState / VvsState / VrsState)：**
| 值 | 含义 |
|----|------|
| 0 | 未运行 |
| 1 | OK |
| 2 | NG |
| 3 | 异常 |

**最终状态 (FinalState)：**
| 值 | 含义 |
|----|------|
| 0 | 待处理 |
| 1 | 最终 OK |
| 2 | 最终 NG |

**测试状态 (TestState)：**
| 值 | 含义 |
|----|------|
| 0 | 未测试 |
| 1 | 一致 |
| 2 | 不一致 |
| 3 | 测试中 |
| 4 | 测试异常 |

## 10. 性能优化要点

1. **单线程队列** — 避免连接竞争，保证写入顺序性
2. **预编译命令** — 高频 UPSERT 操作使用 `Prepare()` 减少解析开销
3. **批量事务** — 批量导入按 100~500 条分批提交，平衡吞吐量与失败影响范围
4. **内存缓存** — `BoardStatCache` 避免频繁聚合查询，增量更新统计
5. **复合索引** — 针对常用查询模式（机台+时间、PanelId+状态）建立覆盖索引
6. **部分索引** — `ProductSerial` 使用 `WHERE NOT NULL` 减少索引体积
7. **连接池** — Npgsql 连接池（1~100），关闭时不重置连接状态
8. **并行解析** — CSV 导入时使用 `Parallel.For` 利用多核加速数据解析
9. **提前序列化** — JSON 序列化在入队前完成，避免占用数据库线程
